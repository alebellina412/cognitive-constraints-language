# Cognitive constraints and efficiency in language statistics

Code and reduced data reproducing every figure and table of

> A. Bellina and V. D. P. Servedio,
> **How the Interplay Between Cognitive Constraints and Efficiency Shapes
> Language Statistics**, *Chaos, Solitons & Fractals*.

A fresh clone reproduces the paper end to end: download three public corpora,
reduce them to compact numeric summaries, and run nine notebooks in order.

---

## What the code computes

From the reduced corpora the code derives every quantity reported in the paper:
the head and tail exponents of the rank-frequency curves of single words in five
languages, together with their fit-window bands; the same statistics for
higher-order *n*-grams, for phrases built by random partition, and for annotated
multi-word expressions; the degree and strength distributions of the word
co-occurrence networks; the position of 22 everyday concepts across the five
languages; the comparison between native speakers and learners at matched corpus
length; and the simulations of the generative model, with the calibration of its
vocabulary scale D₀ by three independent criteria.

## The notebooks

The analysis runs as nine notebooks, in numerical order.

Notebooks 1 to 3 build the datasets: they obtain the corpora and reduce roughly
8 GB of raw text to the few hundred kilobytes of numeric summaries under
`data_reduced/`. Notebook 8 compiles the C simulator and runs the model.
The remaining five read what those write and produce the figures and tables of
the manuscript in seconds. There are only two dependencies between notebooks:
4 to 7 need what 2 and 3 write, and 9 needs what 8 writes.

| notebook | what it does | produces | runtime |
| --- | --- | --- | --- |
| `01_download_raw_data.ipynb` | Obtains the three corpora. SPGC is downloaded and checked against the published checksums; COREFL and PARSEME have no bulk endpoint, so the notebook gives the exact manual procedure | `data_raw/` | 8 GB download, then ~4 min per run to re-verify the archives |
| `02_build_reduced_data.ipynb` | Reduces the raw text to numeric summaries: frequency vectors, *n*-gram counts, network degree and strength, vocabulary-growth curves | `data_reduced/`, Table S1 | ~40 min |
| `03_corpus_controls.ipynb` | The analyses that re-read the raw token streams: exponents at matched corpus length and against lexical richness | Table S3, `rstar_vs_length` | ~11 min |
| `04_zipf_exponents.ipynb` | Fits the head and the tail of the rank-frequency curves and locates the crossover between them | Figure 1, Figure S2, Table S2 | seconds |
| `05_networks.ipynb` | Builds the word co-occurrence networks and fits their degree and strength distributions | Figure 2, Figure S1, Table S6 | seconds |
| `06_phrases_and_concepts.ipynb` | Phrase statistics from the random-partition construction, cross-language concept positions, and the comparison with annotated multi-word expressions | Figure S3, Tables S4 and S9 | seconds |
| `07_learners_vs_natives.ipynb` | Compares learner English (COREFL) with native English (SPGC), with the matched-length control | Figure S4 | seconds |
| `08_simulations.ipynb` | Builds the simulator, runs the four model configurations and the two D₀ calibration sweeps | model trajectories and calibration outputs under `outputs/` | ~1 h, of which ~8 min for the model runs |
| `09_model_and_d0.ipynb` | Compares the calibrated model with the data, estimates D₀ by three criteria, and runs the stationary baselines | Figure 4, Figure S5, Tables S7 and S8 | seconds |

Runtimes are measured on a desktop machine, not estimated. A clone that already
carries `data_reduced/` and the simulation outputs can skip notebooks 1, 2, 3
and 8 altogether: the remaining five regenerate every figure and table in under
a minute. Notebook 8 is the only one that runs the simulator, and its outputs do
not need to be produced twice.

## Quick start

### Requirements

Python 3.10+ and `pip install -r requirements.txt`. Four things outside pip are
also needed, none of them optional where it is used:

| tool | needed by | if it is missing |
| --- | --- | --- |
| `curl` | notebook 1, the SPGC download | checked, and the script stops |
| `gcc`, `make` | notebook 8, building the simulator | `make` fails; the cell reports it |
| **`zstd`** (the CLI) | notebook 8 — every trajectory is written and read through it | the C writer dies on a broken pipe with no clear message |
| `latex` + `dvipng` | optional; figure text | falls back to mathtext, see below |

```bash
pip install -r requirements.txt
jupyter lab notebooks/
```

Then run the notebooks in order. To run one without opening it:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/05_networks.ipynb
```

Figure text is typeset with LaTeX when a `latex` + `dvipng` toolchain is
available, and falls back to matplotlib mathtext otherwise. Set
`FIGSTYLE_USETEX=0` to force the fallback; the figures are then visually
equivalent but not byte-identical to the published ones.

### If you only want to check one figure

Every figure module runs standalone and needs nothing but `data_reduced/`:

```bash
python src/figure_2.py
python src/figure_SI1.py
```

## The data

Three public corpora, none redistributed here. **`docs/DATA.md` is the
authoritative description**: exact versions, download procedures, licences and
the limitations each source imposes.

| corpus | used for | size | acquisition |
| --- | --- | --- | --- |
| **SPGC** 2018-07-18 | everything except Figure S4 and Table S9 | ~8 GB | scripted (`src/download_bulk.py`) |
| **COREFL** v2.0 | Figure S4 | ~4 MB | manual download, scripted import and hash verification |
| **PARSEME** 1.1 | Table S9 | ~97 MB | manual download |

Figure S3 is built from SPGC like the rest: it places the annotated concepts on
the same phrase spectrum Figure 1B plots. Only Figure S4 (COREFL) and Table S9
(PARSEME) come from another corpus.

COREFL and PARSEME have no bulk-download endpoint, so those two fetches are
manual. `docs/DATA.md` gives the click-by-click procedure. All three corpora are
pinned, so you can check that your copy is the one the paper used: SPGC by the
MD5s in `manifests/spgc_checksums.json` (verified by `download_bulk.py --check`),
COREFL by a committed sha256-per-file manifest, PARSEME by a release commit id.

### What is committed, and what is not

Committed: all code, the corpus manifests, and `data_reduced/` — under 700 kB of
numeric summaries. A fresh clone redraws **Figure 1, Figure 2, Figures S1–S3 and
twelve of the tables with nothing else downloaded and nothing else run** (that
is notebooks 04, 05 and 06, in about a minute).

The other three figures need one more thing each, and the notebook that produces
it: Figure S4 needs the length control of notebook 3 — measuring R* on the
native corpus truncated to a range of lengths means re-reading the raw tokens —
while Figure 4 and Figure S5 need the simulated runs and the D₀ sweeps of
notebook 8.

Not committed: the raw corpora (`data_raw/`), the simulated trajectories, and the
outputs of the D₀ sweeps. Notebook 8 regenerates them from the C source. This is
deliberate — the model results are reproduced from the simulator rather than
taken on trust — and it is why notebook 8 costs an hour while most of the others
cost seconds.

### Two conventions worth knowing before reading the code

**All estimators live in `src/fits.py`.** Nothing computes an exponent anywhere
else, so the same window and the same convention apply to a corpus curve and to a
simulated one — the model/data comparison is like-for-like by construction rather
than by inspection.

**Uncertainties are fit-window bands, not standard errors.** Every exponent is
reported as *central value* [*band*], where the band is the spread over a set of
a-priori reasonable fit windows. The nominal OLS standard error assumes
independent residuals, which a smooth log-log curve does not have; it understates
the real uncertainty by roughly two orders of magnitude. Where the paper says two
estimates agree or disagree, it means their bands overlap or do not.

## The model

`sim/` holds the Urn Model with Triggering in C. The production version,
`sim/optimized/UMT_dynamic_fast_zstd.c`, preserves the stochastic rules, fixed
seed and initial urn of the archived simulator and changes only the
representation: a Fenwick tree for the urn weights, so draws and updates are
O(log D) rather than scans with global renormalisation, and a `uint32` history so
stream draws are O(1). Trajectories are written as Zstandard-compressed `CLTRJ1`.

`sim/tests/` holds two regression scripts that compare the fast version against
the archived one byte for byte on short runs. Run them after touching anything in
`sim/`:

```bash
make -C sim
bash sim/tests/verify_roundtrip.sh
bash sim/tests/verify_fast_urn_equivalence.sh
```

Trajectories are intermediates: `src/build_reduced_sim.py` reduces each one to the
*same* on-disk schema that `build_reduced.py` produces from the corpus, then
deletes it.

### The two D₀ sweeps

`src/calibrate_d0.py` is run twice, over two different grids, and **neither
sweep is a coarse version of the other**. Both `--config` and `--tag` are
required precisely so that they cannot be confused:

| sweep | grid | seeds | records `rstar_sim` | read by |
| --- | --- | ---: | --- | --- |
| `--tag crossover` (`manifests/d0_calibration.json`) | 14 values, 200–26,000 | 2 | **yes** | `figure_SI5.py`, `model_vs_data.py` |
| `--tag refined` (`manifests/d0_calibration_refined.json`) | 24 values on each minimum | 6 | no | `estimate_d0.py` |

The wide one has to reach down to 200, because that is where the crossover
criterion puts the learners, and it is the only one carrying the crossover of
each simulated curve. The deep one exists for its six seeds: with two, the
learners' competitive range collapses onto a single grid point. Refining does
**not** sharpen D₀ — the natives come out at 9,366 with the same
[6,664–13,163] range on either grid, because the limit is the flatness of the
objective and not the spacing of the grid.
